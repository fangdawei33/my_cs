`my_cs` 用来整理我的计算机课程笔记、配套实验、生活随笔和学习资源。首页是叶臧的个人介绍，采用暖色手绘风格，提供“课程笔记”“生活”“资源”三个入口和一个“待开发”位置。课程列表放在[独立的课程目录页](https://fangdawei33.github.io/my_cs/courses/)；每门课程与生活笔记使用独立的 mdBook，资源页提供 PDF 原文件下载。

首页下方有两个独立的展示窗口，当前分别展示动态壁纸视频和原创插画。每个窗口都能添加多张图片或视频，支持自动轮播、手动切换与暂停。


2024年12月份有了自己的第一篇博客园，也第一次解除了github，当时的c语言课设的第一版就上传到了上面，纯豆包生成2000多行，后续由于代码漏洞太多放弃了上传了。

后续是在大一的暑假，开始在csdn上写文章，但也不了了之。

我一直想拥有一个自己的网页，尤其是在今年年初（2026），当时还没考完期末考试，很挣扎，找的绿裙群主的教程，后来发现还是不合我心意。

也得益于ai的发展哈，希望这个可以完成我都夙愿吧。

## 生活笔记

[进入生活笔记](https://fangdawei33.github.io/my_cs/life/)

生活内容放在与 `courses/` 并列的 `life/` 中，独立管理随笔和文章目录，共用阅读主题，不计入课程数量。

网站顶部的“生活”会直接打开独立的生活笔记页面；首页下方的生活卡片也可以进入这个页面。

```text
life/
├── book.toml                 # 生活笔记的书名、作者与主题配置
└── src/
    ├── SUMMARY.md            # 左侧目录
    ├── introduction.md       # 生活笔记首页
    ├── essays/
    │   └── README.md         # 随笔目录；自己的文章也放在这个文件夹
    └── writing-template.md   # 写作与配图示例
```

例如，新建 `life/src/essays/first-entry.md` 写一篇随笔，然后在 `life/src/SUMMARY.md` 中添加：

```markdown
- [随笔](essays/README.md)
  - [我的第一篇随笔](essays/first-entry.md)
```

也可以在 `life/src/essays/README.md` 中补上文章链接，方便从随笔目录页阅读。图片放入 `life/src/images/`，在随笔中使用 `../images/图片名` 引用。写作示例见 [生活写作模板](life/src/writing-template.md)。

`npm run dev` 会同时构建课程和生活笔记。本地阅读地址为 <http://localhost:3000/life/>。如果是在预览服务运行期间加入生活模块，请先按 `Ctrl+C`，再重新运行 `npm run dev`，让新的构建与监听逻辑生效。

## 教材与学习资源

[资源目录](https://fangdawei33.github.io/my_cs/resources/)

资源是与“课程笔记”“生活”并列的独立页面，按课程与资料集分类，支持按教材名、作者搜索和分类筛选。相应课程的介绍页也有教材入口；点击后按课程名筛选资源，清空搜索框即可查看全部资料。PDF 保持原有格式、图片与排版。

普通中文课程名可以直接写在链接里，无需自己查找或生成 URL 编码。例如在编译原理的课程介绍页中写：

```markdown
[查看本课程的 PDF 教材与资料](../resources/?q=编译原理)
```

`q=` 后面是资源页要搜索的课程名。给同一门课新增教材时，这个入口不用改；上传并发布更新后的资源目录，原入口就能找到新教材。

**非商用，仅供自主学习使用。** 教材及资料的版权归原作者、出版方或相应权利人所有。此用途说明不改变各文件原有的版权和许可，详见[资源用途与版权声明](resources/NOTICE.md)。

```text
resources/
├── index.html        # 资源页模板
├── catalog.json      # 标题、分类、大小、内容哈希和下载地址
├── NOTICE.md         # 非商用、自主学习与版权声明

```

在项目根目录运行 `npm run dev`，打开 <http://localhost:3000/resources/> 可查看本地资源目录。点击“下载 PDF”保存到电脑，再用本地阅读器打开；网站不提供 PDF 网页阅读器。本地资源通过同盘硬链接提供下载，不会在每次构建时再复制一份大型教材。

本项目使用 GitHub Releases 存放 PDF 附件，网站只提供目录和下载入口。通过官方 GitHub CLI 登录后，可运行：

```powershell
npm run resources:publish
```

脚本会校验原件、创建或继续使用 `learning-resources-v1` 草稿、跳过已上传且大小相符的附件。全部上传并校验完成后，再发布附件并自动把下载地址写入 `catalog.json`。中断后可以重新运行续传。发布完成后，构建网站并提交更新后的资源目录即可。

上传时需要保持电脑开机并联网。已上传完成的文件会被跳过；正在传输的单个文件如果中断，需要重新上传。附件发布后，可以在 [GitHub Releases](https://github.com/fangdawei33/my_cs/releases/tag/learning-resources-v1) 查看完整附件列表，或从资源页选择所需教材下载到本地阅读。

以后导入新的 PDF，可以执行：

```powershell
npm run resources:import -- --category 数据库 --course 数据库 "C:\资料\教材.pdf"
```

这条命令是在项目根目录中执行，把电脑上的 PDF 复制到本地资源目录，并关联到指定课程：

- `--category 数据库`：在资源页中归入“数据库”分类。
- `--course 数据库`：关联已有的 `courses/数据库/` 课程。
- `"C:\资料\教材.pdf"`：换成你电脑上 PDF 的实际完整路径，保留两边的引号。

文件夹路径也支持，脚本会递归收集 PDF，并按内容去重。`--category` 为资源分类，`--course` 为现有课程的目录名；例如机器学习使用 `machine-learning`。导入只复制原件，不转换成 Markdown。

新增资料的顺序为：导入 PDF → 运行 `npm run resources:publish` 上传附件 → 运行 `npm run build` 和 `npm run check` → 提交更新后的 `catalog.json` 并推送。PDF 原件放在本地 `resources/files/`；Git 仓库保存页面、说明和资源目录，GitHub Pages 发布网站，GitHub Releases 保存附件。

## 本地启动（Windows PowerShell）

需要 Node.js 22 或更新版本。无需 `npm install`，项目没有 npm 第三方依赖。

```powershell
cd D:\ml_learning\my_cs
npm run setup
npm run dev
```

`setup` 从官方 GitHub 下载固定版本 mdBook 0.4.52 到项目的 `.tools/`，不修改系统 PATH。首次下载需要联网；同一项目已安装后无需重复下载。

终端出现“本地预览”地址后，打开：

| 页面 | 本地地址 |
| --- | --- |
| 网站首页 | <http://localhost:3000/> |
| 课程目录 | <http://localhost:3000/courses/> |
| 机器学习 | <http://localhost:3000/machine-learning/> |
| 生活笔记 | <http://localhost:3000/life/> |
| 资源目录 | <http://localhost:3000/resources/> |

命令要在包含 `package.json` 的 `D:\ml_learning\my_cs` 中执行。如果报 `ENOENT`、找不到 `package.json`，先检查当前目录，执行上面的 `cd` 命令再启动。

修改正文、目录、主题或首页后，脚本自动构建；等待终端显示“完成”后刷新浏览器。按 `Ctrl+C` 停止。修改 `scripts/` 中的构建或预览代码后，需要停止并重新启动服务。

如果 PowerShell 阻止执行 `npm.ps1`，使用 `npm.cmd` 代替 `npm`，不必修改系统执行策略。

端口冲突时：

```powershell

```

## 修改网页界面

GitHub 仓库介绍和笔记网站首页分别由不同的文件控制：

| 想修改的内容 | 编辑位置 |
| --- | --- |
| GitHub 仓库介绍、封面、徽章、课程目录 | `README.md`，封面图片放在根目录 `assets/` |
| 网站首页的文字、导航和区域顺序 | `index.html`，内有中文注释和增删说明 |
| 网站首页的颜色、字体、间距、布局 | `web/home.css` |
| 首页、课程目录、资源页共用的配色和导航样式 | `web/site.css` |
| 首页两个展示窗口的轮播交互 | `web/home.js` |
| 首页展示的图片、视频、说明与切换间隔 | `web/gallery.json` |
| 课程目录的布局、搜索和快捷键 | `courses/index.html`、`web/courses.css`、`web/courses.js` |
| 网站标题、描述、昵称、个人介绍 | `site.json` 中的 `title`、`description`、`nickname`、`introduction` |
| 课程卡片的名称、简介、排列顺序 | 对应课程的 `course.json` |
| 课程和生活文章的阅读样式 | 根目录 `theme/` |

首页导航中的两类链接用途不同：

```html
<!-- 在当前首页内滚动到“关于这里” -->
<a href="#about">关于这里</a>

<!-- 打开独立的课程目录、生活笔记、资源页面 -->
<a href="./courses/">课程笔记</a>
<a href="./life/">生活</a>
<a href="./resources/">资源</a>
```

网站首页使用的图片放在 `web/` 中，HTML 中按 `./assets/图片名` 引用。构建时 `web/` 会复制成 `dist/assets/`；根目录用于 README 的 `assets/` 不会自动发布到网站。

模板中的 `{{title}}`、`{{nickname}}` 等由构建脚本填充。首页的 `{{gallery_panels}}` 来自 `web/gallery.json`；课程目录页的 `{{course_cards}}` 由脚本读取课程配置生成。自定义课程卡片的 HTML 结构时，修改 `scripts/build.mjs` 中生成 `cards` 的部分。

### 给首页添加图片和视频

两个窗口分别对应 `web/gallery.json` 中 `panels` 数组的第一项和第二项。每个窗口的 `items` 是素材列表；把文件放进 `web/media/`，再往对应列表里添加一项即可。路径相对 `web/`，不要写电脑上的 `C:\...` 或 `D:\...`。

例如把 `旅行.jpg` 和 `日常.mp4` 放入 `web/media/`，某个窗口的 `items` 可以写成：

```json
"items": [
  {
    "type": "image",
    "src": "media/旅行.jpg",
    "caption": "留住一个喜欢的瞬间。",
    "alt": "对图片内容的简短说明"
  },
  {
    "type": "video",
    "src": "media/日常.mp4",
    "caption": "今天的小片段。",
    "alt": "对视频内容的简短说明"
  }
]
```

这是配置片段，用它替换相应窗口的 `items`，不要替换整个文件。相邻素材之间用英文逗号分隔，最后一项后面不加逗号。`type` 填 `image` 或 `video`，`caption` 是下方文字，`alt` 是内容说明；视频还可以添加 `poster` 字段指定封面图，路径写法相同。

顶层的 `intervalSeconds` 控制图片切换间隔，默认 8 秒。视频至少展示一遍完整时长再切换；单个视频会静音循环播放。窗口有多个素材时才显示上一张、下一张和暂停轮播按钮；鼠标停留、键盘操作或切到其他标签页时会暂停切换。视频离开可见区域会暂停，支持进度条、音量和全屏控件；系统启用减少动态效果或节省流量时，由读者手动播放。

当前使用 1080P 动态壁纸，约 44 MB；4K 原文件保留在原目录。网页用的副本放在 `web/media/wallpaper-1080p.mp4`。图片支持 PNG、JPG、WebP、GIF 等，视频支持 MP4、WebM；首次使用的新视频应先在浏览器确认能播放。

修改源文件后使用本地预览检查；`dist/` 是自动生成的网页，请通过源文件修改网站。

## 写一篇笔记

1. 在对应课程的 `src/` 中创建 Markdown 文件。
2. 在该课程的 `src/SUMMARY.md` 添加链接；缩进表示子章节。
3. 图片放在该课程的 `src/images/`，文章中用相对路径引用。
4. 实验放在 `experiments/`，按主题组织。

机器学习书内有「笔记写作模板」，可复制其结构。右侧目录由正文 `##`、`###` 标题生成，至少有两个小标题时显示；屏幕较窄时隐藏。

公式使用 mdBook 内置的 MathJax，首次加载需要联网获取 MathJax。示例语法：

```text
行内：\\( y = wx+b \\)
块级：\\[ L = \frac{1}{n}\sum_i (\hat y_i-y_i)^2 \\]
```

实验文件发布后的路径为 `<课程目录>/experiments/...`。若在 `src/practice.md` 中链接，可写成：

```markdown
[下载 Notebook](experiments/linear-regression/study.ipynb)
```

这种链接指向构建后复制的文件，应通过本地网站预览。GitHub 的源码 Markdown 预览不会解析这个发布路径。

## 新增一门课程

```powershell
npm run new-course -- 计算机视觉
```

上面的命令会创建 `courses/计算机视觉/`，显示名称也是“计算机视觉”。如果希望目录名和显示名称不同，可以改用下面的写法；两种方式任选一种：

```powershell
npm run new-course -- computer-vision "计算机视觉" "记录视觉模型、图像处理与配套实验。"
```

目录名支持中文、小写英文、数字和连字符。省略第二个参数时，显示标题默认与目录名相同，因此也可以只写一次中文课程名。中文网址可以正常访问，浏览器或复制链接时可能显示为百分号编码。

命令会创建 `course.json`、`book.toml`、目录、介绍页、首篇笔记和实验目录。课程目录页与构建自动发现所有课程，不需要逐个添加发布任务。

已存在的课程不会被覆盖。网站的课程目录页会自动出现新课，README 上方的分类课程表则需要手动补充对应链接。

- `course.json` 的 `title`、`description` 控制课程目录中的卡片。
- `order` 数字越小，卡片越靠前。
- `book.toml` 的 `title` 控制书内标题。
- 新课也使用根目录 `theme/`，修改一次可应用到所有课程。

各课程内和 `life/` 内的 `theme/` 是构建脚本自动生成的资源副本，已忽略提交；只修改仓库根目录的 `theme/`。请使用 `npm run dev` 或 `npm run build`，它们会先同步主题，再调用 mdBook。`courses`、`life` 和 `resources` 已作为课程目录、生活与资源模块的保留路径，新增课程请使用其他目录名。

## 构建与检查

```powershell
npm run build
npm run check
```

`build` 会生成网站首页、课程目录、全部课程和生活笔记；`check` 检查生成网页中的相对链接及本地资源。构建前还会检查目录引用的 Markdown 是否存在。`dist/` 可直接作为静态网站部署。

左侧目录由 `SUMMARY.md` 生成，并通过单独的 `toc.js` 加载。构建脚本会给目录资源加上随内容变化的版本号，避免更新目录后浏览器仍使用旧缓存。若刚部署后仍看到旧页，可以按 `Ctrl+F5` 强制刷新。

构建辅助逻辑的回归检查可运行 `npm test`，GitHub Actions 也会执行。

在自己的 GitHub Pages 仓库路径下构建时，设置基路径以保证 404 页资源链接正确：

```powershell
$env:SITE_BASE_PATH = '/my_cs'
npm run build
Remove-Item Env:SITE_BASE_PATH
```

首页与正常文章使用相对链接；GitHub Actions 会自动根据仓库名称设置基路径。

三个步骤分别是：暂存改动、创建提交、推送到 GitHub。只有 `git add` 而没有 `git commit` 时，`git push` 不会推送尚未提交的修改。可以用 `git status` 查看当前状态。
