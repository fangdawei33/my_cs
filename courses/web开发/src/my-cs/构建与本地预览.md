# 05 构建脚本与本地预览

这一章沿着你实际输入的命令往下追踪。先把项目运行起来，再理解 Node.js、npm、mdBook 和 `dist/` 在中间各做了什么。

## 1. 先确认终端在哪里

打开 PowerShell，输入：

```powershell
cd D:\ml_learning\my_cs
```

`cd` 表示切换当前目录。终端前面的提示应类似：

```text
PS D:\ml_learning\my_cs>
```

之后再运行项目命令。`PS ...>` 只是提示符，不需要一起复制。

若想确认自己在哪、目录里有什么，可以输入：

```powershell
Get-Location
Get-ChildItem
```

这里应能找到本项目的 `package.json`。它是理解 npm 命令的入口。

## 2. Node.js 和 npm 各做什么

**Node.js** 让 JavaScript 可以在浏览器之外运行。本项目用它读写文件、调用 mdBook、建立本地 HTTP 服务。概念介绍见 [Node.js 官方入门](https://nodejs.org/learn/getting-started/introduction-to-nodejs)。

**npm** 在本项目里主要作为命令入口。`package.json` 把常用操作取了便于记忆的名字。

先检查命令是否可用：

```powershell
node --version
npm.cmd --version
```

项目要求 Node.js 22 或更新版本，GitHub 工作流目前使用 Node.js 22。只要现有环境满足项目要求，不需要因为写一篇笔记而反复重装。

PowerShell 下如果 `npm` 对应的 `npm.ps1` 被执行策略阻止，可用 `npm.cmd` 调用。同一项项目操作，两种入口的用途相同，通常无需为了运行它去更改整个系统的执行策略。

## 3. npm run 是怎样找到具体代码的

打开 `package.json`，能看到类似下面的设置：

```json
"scripts": {
  "setup": "node scripts/setup.mjs",
  "build": "node scripts/build.mjs",
  "check": "node scripts/check.mjs",
  "dev": "node scripts/serve.mjs",
  "new-course": "node scripts/new-course.mjs"
}
```

这是完整 JSON 文件的一部分。`scripts` 中每个键是一个命令名，每个值是要执行的命令。

因此：

```powershell
npm.cmd run dev
```

会按照项目配置执行：

```powershell
node scripts/serve.mjs
```

`dev` 是项目自己选的名字；换一个项目，同名命令也可能调用另一套工具。解释方式可对照 [npm 官方 run-script 文档](https://docs.npmjs.com/cli/v10/commands/npm-run-script/)。

文件扩展名 `.mjs` 表示这里使用 JavaScript 模块。你可以看到 `import` 把其他模块中的功能引进来，例如从 `node:fs` 引入文件操作。

## 4. 第一次准备与平时启动

初次准备本项目，或者本地 mdBook 工具缺失时：

```powershell
cd D:\ml_learning\my_cs
npm.cmd run setup
```

这个命令执行 `scripts/setup.mjs`：按操作系统下载官方的 mdBook 0.4.52，解压到项目自己的 `.tools/`，随后确认版本。Windows 对应的工具文件是 `.tools/mdbook.exe`。

首次下载需要联网；该版本已经安装好时，脚本会识别并直接结束，不再重复下载。

准备好后，日常预览运行：

```powershell
npm.cmd run dev
```

等待终端输出“本地预览”地址，再打开：

```text
http://localhost:3000/
```

当前项目的 npm 配置没有第三方包依赖，已经写好的脚本主要使用 Node.js 内置模块。因此当前说明没有要求先执行 `npm install`。以后若项目增加依赖，应跟随当时的配置和安装说明。

## 5. build.mjs：把多本笔记汇总成一个站点

直接生成网页，可以运行：

```powershell
npm.cmd run build
```

它执行根目录的 `scripts/build.mjs`。按现在的实际代码，主要工作是下面这些。

### 第一步：读取课程与生活笔记

`scripts/lib.mjs` 提供 `getCourses()` 和 `getLifeBook()`。它们查找课程目录，读课程元信息，并核对书的 `SUMMARY.md` 中引用的 Markdown 文件。

课程按 `order` 等信息排序，之后用同一份课程清单构建各本书和课程卡片。

### 第二步：准备新的 dist

脚本确认目标是项目内的普通 `dist/` 目录，然后清理旧产物、重新生成。这样可以防止旧版本已经删除的页面长期残留。

所以直接编辑 `dist/` 的内容，下次构建可能就被覆盖；源文件中的修改才能重新生成出来。

### 第三步：逐本调用 mdBook

每门课都用自己的 `book.toml` 和 `src/` 构建。结果汇总到：

```text
dist/课程目录/
```

生活笔记类似，放到 `dist/life/`。脚本还会同步共用主题，复制课程的 `experiments/` 作为下载文件。

### 第四步：生成首页与课程目录页

首页模板中可以看到：

```html
<h1>你好，我是<span>{{nickname}}</span>。</h1>
```

脚本从 `site.json` 读到昵称，再把 `{{nickname}}` 替换成实际文字。

全部课程的目录模板中，则有 `{{course_cards}}`。构建脚本为课程生成卡片 HTML，再填进去。

这些双大括号是本项目脚本约定的占位符。浏览器自己打开源模板，不会自动知道应该用什么值替换它。

### 第五步：复制公共素材、生成资源清单

`web/` 复制到 `dist/assets/`。资源模块读取 `resources/catalog.json`，生成 `dist/resources/index.html`，里面的下载按钮指向相应附件地址。

最后再写入 `.nojekyll` 等站点文件，本次构建结束。

## 6. dist 到底有什么用

它是**构建完成、准备给浏览器使用的网站文件集合**。可以把它看作本地预览与部署共同使用的输出目录。

一个简化的产物结构是：

```text
dist/
├── index.html
├── assets/
├── courses/
│   └── index.html
├── web开发/
│   ├── index.html
│   ├── first-note.html
│   ├── my-cs/
│   ├── demos/
│   └── ...
├── life/
└── resources/
```

### 以前没看到 dist，为什么也能转换

mdBook 本身可以把 Markdown 生成 HTML；输出目录可以配置，也可以通过命令指定。my_cs 选择统一输出到 `dist/`，方便一个站点同时容纳多本书和公共首页。

“没有手动创建这个文件夹”也可能只是因为工具自动创建了它。重要的是区分输入在哪里、输出在哪里，而不是某个文件夹必须永远使用特定名字。

### 它为什么不提交到 Git

`.gitignore` 里忽略了 `dist/`。仓库保留可维护的源文件，GitHub Actions 会重新构建产物，再把产物发布为站点。

因此，`dist/` 很重要，但通常不需要在源码仓库里保存每一次构建生成的大量重复文件。

## 7. serve.mjs：把 dist 提供给本机浏览器

`npm.cmd run dev` 执行的 `serve.mjs`，首先会调用构建函数，然后启动一个本地 HTTP 服务。

```text
运行 dev
   ↓
先构建 dist/
   ↓
在本机监听 127.0.0.1:3000
   ↓
浏览器访问 localhost:3000
   ↓
服务从 dist/ 查找并返回文件
```

`localhost` 表示本机。这里的 `3000` 是端口号，用来区分同一台电脑上不同的网络服务。

本项目预览服务绑定在 `127.0.0.1`，主要供这台电脑自己访问。它的运行不等于已经把站点发布给所有人。

服务会返回相应文件类型，例如 HTML、CSS、PNG、MP4。视频还支持按字节分段读取，便于浏览器请求某段内容和拖动播放进度。

## 8. 保存之后，页面为什么没立刻变化

这里有三个阶段：

1. 编辑器把修改保存到源文件。
2. 预览脚本发现受监控的文件变化，重新构建。
3. 浏览器刷新，重新请求构建后的文件。

当前项目会自动重新构建，但没有给浏览器接入自动刷新功能。保存后等终端显示完成，再手动刷新网页。

脚本主要监控课程、生活、主题、`web/` 和部分根目录配置。修改 `scripts/` 里的构建或服务代码时，要先停止，再重新启动预览，才能运行更新后的脚本逻辑。

## 9. 每条常用命令负责一个环节

| 命令 | 做什么 | 是否一直运行 |
| --- | --- | --- |
| `npm.cmd run setup` | 准备项目本地 mdBook | 完成后结束 |
| `npm.cmd run build` | 生成一次完整网站 | 完成后结束 |
| `npm.cmd run check` | 检查已生成网页中的本地链接和资源 | 完成后结束 |
| `npm.cmd run dev` | 构建、启动本机预览、监听修改 | 通常保持运行 |
| `npm.cmd test` | 运行项目已有的脚本逻辑测试 | 完成后结束 |

`check` 需要已有构建结果。新一轮完整的静态链接检查通常按顺序执行：

```powershell
npm.cmd run build
npm.cmd run check
```

它会检查文件链接是否存在，但不能代替对文章内容、视觉布局、视频编码或所有交互的判断。

## 10. 停止与更换端口

在运行预览的终端按 `Ctrl+C` 停止服务。

如果 3000 端口已被其他服务占用，可以指定一个不同端口：

```powershell
npm.cmd run dev -- --port 3001
```

之后打开 `http://localhost:3001/`。命令里的第一个 `--` 把后面的参数传给项目脚本；`--port 3001` 是本项目预览脚本识别的参数。

改变端口后，浏览器地址也要一起改。打开旧端口，看到的可能是另一套服务提供的旧页面。
