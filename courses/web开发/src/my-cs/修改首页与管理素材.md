# 06 修改首页与管理图片视频

掌握前面几章后，就可以带着具体目标修改首页：想改文字，先找文字来源；想改颜色，先找 CSS；想加素材，先看素材配置。

本章针对当前项目的个人介绍首页。课程正文仍由 mdBook 管理，两套页面各有自己的源文件。

## 1. 先用对照表选文件

| 希望修改什么 | 修改位置 |
| --- | --- |
| 昵称、首页介绍 | 根目录 `site.json` |
| 首页区域顺序、板块名称、链接 | 根目录 `index.html` |
| 首页卡片、介绍区、画面窗口的布局 | `web/home.css` |
| 首页、课程目录、资源页的共同配色和导航 | `web/site.css` |
| 课程目录页结构 | `courses/index.html` |
| 课程目录页的样式与搜索逻辑 | `web/courses.css`、`web/courses.js` |
| 轮播素材及说明 | `web/gallery.json` |
| 轮播的浏览器行为 | `web/home.js` |
| 从轮播配置生成 HTML 的代码 | `scripts/homepage.mjs` |
| 课程正文的共用阅读样式 | 根目录 `theme/` |

先改与你目标最接近的文件，观察结果后再扩大范围。例如只改一句自我介绍，不需要同时修改所有 CSS。

## 2. 改昵称与介绍：认识 JSON

`site.json` 当前主要有这几个字段：

```json
{
  "title": "my_cs",
  "description": "叶臧的学习与生活记录：课程笔记、生活随笔，以及慢慢积累的学习资料。",
  "nickname": "叶臧",
  "introduction": "在这里记录学习，也收藏日常。把学过的知识慢慢变成自己的理解，把值得记住的小事好好留下。"
}
```

它们是一组“键和值”：左边是字段名，右边是内容。

- `title`：网站名称。
- `description`：页面描述等位置使用的说明。
- `nickname`：首页标题中的昵称。
- `introduction`：首页介绍段落。

JSON 中的字符串使用英文双引号。相邻字段之间用英文逗号，最后一个字段后面不加逗号。标准 JSON 不支持直接插入 `// 这是一条注释`。

中文文字可以正常写进字符串。标点符号若出现在字符串内部，是普通内容；作为 JSON 结构使用的引号、冒号、逗号则要符合语法。

例如要写含有英文双引号的内容，需要转义：

```json
{
  "introduction": "今天终于弄懂了 \"构建\" 是什么。"
}
```

这是字段写法示例，实际修改时保留文件中需要的其他字段。

## 3. 占位符是怎样联系到配置的

根目录 `index.html` 里可以看到：

```html
<h1 id="welcome-title">你好，我是<span>{{nickname}}</span>。</h1>
<p class="welcome-description">{{introduction}}</p>
```

构建脚本读取 `site.json`，再将双大括号中的名字替换为实际内容，最后保存到 `dist/index.html`。

因此，你编辑的是昵称字段，页面中的 HTML 结构仍然保持；你编辑 HTML，则可以改变标题结构和区域排列。

如果随便增加一个 `{{motto}}` 占位符，却没有让构建脚本提供对应的值，这个名字不会凭空变成一句格言。对于固定的小段文字，可以直接写在 HTML 中；确实需要统一配置时，再调整配置和构建逻辑。

## 4. 改入口与区域：认识 a、class 和 id

当前一个板块入口的基本结构类似：

```html
<a class="module-card module-courses" href="./courses/">
  <img
    src="./assets/illustrations/courses.png"
    alt=""
    width="180"
    height="180"
  >
  <h3>课程笔记</h3>
  <p>把知识一点点想明白</p>
</a>
```

- `a` 包住整张卡片，让卡片成为链接。
- `href` 决定打开哪里。
- `class` 让 CSS 可以找到这类卡片。
- `img` 的 `src` 指向图片，`alt` 提供图片的文字替代。
- `h3` 和 `p` 是卡片中的标题、说明。

这里的图片主要装饰已经有清楚文字说明的入口，因此使用空 `alt`，避免辅助阅读工具重复朗读同一份信息。正文里有知识含义的示意图，应写具体的图片说明。

当前“待开发”卡片使用展示用的 `article`。将来确实新增了一个页面，再将它改成带有效 `href` 的链接。

### 新增区域与新增页面

想在同一页加“我的兴趣”，可以新增一个 `section`，给它一个唯一 id，再从导航用 `#这个id` 定位。

想独立打开一页，则需要建立对应页面，并让构建和发布能包含它，导航写到那个页面的地址。仅仅在顶部加一段导航文字，还没有创建目标页面。

## 5. 改样式：先找选择器

假设你想调整四张板块卡片之间的距离，可以在 `web/home.css` 中查找：

```css
.module-grid {
  display: grid;
  grid-template-columns: repeat(4, minmax(0, 1fr));
  gap: 24px;
}
```

这是当前布局的核心写法：

- `display: grid`：使用网格排版。
- `repeat(4, ...)`：将可用位置分成四列。
- `1fr`：每列分到一份剩余空间。
- `gap`：网格项目之间的距离。

如果修改后手机上仍是另一种列数，继续查找后面的 `@media`。同一选择器在不同屏幕条件下可以有不同规则。

改背景色时，可以先看 `web/site.css` 顶部的 CSS 自定义属性：

```css
:root {
  --ink: #493f36;
  --paper: #fff9f0;
}

body {
  background: var(--paper);
  color: var(--ink);
}
```

`--paper`、`--ink` 是自己给颜色取的名字，`var(...)` 表示使用对应的值。这样多处页面可以共用同一套配色。

**先改一个值，保存、构建、刷新，再观察结果。** 如果一次改很多选择器，排版出问题时就更难定位原因。

## 6. 首页图片应放在哪里

假设你准备了一张 `旅行.jpg`，希望首页使用它，可以保存到：

```text
web/media/旅行.jpg
```

首页 HTML 中的引用为：

```html
<img src="./assets/media/旅行.jpg" alt="旅行时拍摄的山间风景">
```

这里源文件夹叫 `web`，HTML 却写 `assets`，是因为构建脚本执行：

```text
web/ → dist/assets/
```

根目录 `assets/` 中的 README 封面有自己的用途，继续保留。首页素材与封面不用互相搬来搬去。

## 7. 两个展示窗口怎样配置

`web/gallery.json` 的顶层是一个对象，其中 `panels` 是数组；数组里的第一项和第二项分别对应左右两个窗口。

每个窗口的 `items` 也是数组，表示这个窗口按什么顺序展示素材。

下面是一份有效的配置示例：左边继续放现有视频，右边放两张已有插画，方便理解多素材的写法。

```json
{
  "intervalSeconds": 8,
  "panels": [
    {
      "title": "会动的风景",
      "items": [
        {
          "type": "video",
          "src": "media/wallpaper-1080p.mp4",
          "caption": "让喜欢的风景，在这里多停留一会儿。",
          "alt": "循环播放的动态壁纸"
        }
      ]
    },
    {
      "title": "日常的小画面",
      "items": [
        {
          "type": "image",
          "src": "illustrations/riverside.png",
          "caption": "认真学习，也别错过窗外的好天气。",
          "alt": "小猫和小熊在河边休息"
        },
        {
          "type": "image",
          "src": "illustrations/life.png",
          "caption": "收藏一点日常的小快乐。",
          "alt": "小猫和小熊一起野餐"
        }
      ]
    }
  ]
}
```

请注意，教程展示这份配置，并不会自动修改正在使用的首页。真的要增加素材时，才编辑根目录的 `web/gallery.json`。

## 8. 每个素材字段怎么填

| 字段 | 用途 | 例子 |
| --- | --- | --- |
| `type` | 素材类型 | `image` 或 `video` |
| `src` | 相对 `web/` 的文件路径 | `media/旅行.jpg` |
| `caption` | 窗口下方的说明文字 | `今天的小片段。` |
| `alt` | 图片或视频的简短内容说明 | `傍晚湖边的树影` |
| `poster` | 视频可选的封面图片 | `media/视频封面.jpg` |

例如新增一个本地视频，先把文件复制进 `web/media/`，再在目标窗口的 `items` 中增加对象。路径写 `media/文件名.mp4`，不写电脑的绝对路径，也不在这里额外加 `assets/`。

当前配置有两个窗口，每个窗口至少需要一个素材。删除其中一个素材时，要保持它所在的列表仍然有效；需要改成一种新的页面布局，再相应调整模板和脚本。

## 9. 自动轮播、视频循环和播放控件是三回事

- **素材轮播**：一个窗口有多个素材时，在它们之间切换。
- **视频循环**：同一个视频播完后，再次播放。
- **视频控件**：读者自己暂停、拖动进度或进入全屏。

当前脚本中，图片按 `intervalSeconds` 指定的间隔切换，视频至少展示一个完整时长后再切换。每个窗口只有一个素材时，切换按钮会隐藏。

视频使用静音、循环和行内播放设置，在可见区域内尝试自动播放；浏览器限制自动播放时，读者仍可操作播放控件。素材窗口不在可见区域、标签页隐藏时，会暂停相应的播放或自动切换。

这部分 HTML 由 `scripts/homepage.mjs` 在构建时生成，浏览器里的切换由 `web/home.js` 负责。一个发生在“生成页面”时，一个发生在“读者打开页面”后。

## 10. 为什么有的修改刷新后没有保留

几种操作发生的位置不同：

| 修改方式 | 作用范围 |
| --- | --- |
| 修改源文件后重新构建 | 下次构建和发布继续保留 |
| 修改 `dist/` 中生成的 HTML | 下次构建可能被覆盖 |
| 在浏览器开发者工具中临时改样式 | 用于试效果，一般不会写回源文件 |
| 仅保存本地文件 | 本地有改动，GitHub 还未收到 |

从开发者工具试出合适的样式后，要回到源 CSS 文件保存。确认效果，再按下一章的[提交与发布流程](Git与GitHub发布.md)更新线上站点。
