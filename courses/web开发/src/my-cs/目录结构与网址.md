# 02 看懂项目目录与网址

打开项目时，最容易产生的困惑是：有很多 `index.html`，也有两种 `assets`，课程里面还有 `src`、`theme`、`experiments`。它们服务于不同的页面和阶段。

本章先分组，再把源文件与网址一一对应起来。

## 1. 从项目根目录开始

“根目录”在这里指 my_cs 文件夹最外面这一层。当前本地路径是：

```text
D:\ml_learning\my_cs
```

用 VS Code 打开这一整个文件夹，左侧应该能看到 `package.json`、`README.md`、`courses`、`scripts` 等内容。

这里的根目录，与 Windows 的 `D:\`、网站地址的 `/` 分别属于不同语境。操作前先明确自己正在讨论文件夹还是网址。

## 2. 把项目文件分成四组

### 第一组：要阅读的内容

```text
courses/          各门课程
life/             生活笔记
resources/        教材与资料清单
```

课程正文主要在 `courses/某门课/src/`，生活正文在 `life/src/`。资源清单使用 `resources/catalog.json` 记录资料信息。

### 第二组：网页的入口、外观和交互

```text
index.html        网站首页模板
site.json         网站名称、昵称、首页介绍
web/              首页、课程目录、资源页使用的 CSS、JS 和素材
theme/            所有课程和生活笔记共用的阅读主题
assets/           根目录 README 使用的封面等图片
```

### 第三组：把网站组织起来的工具

```text
package.json      声明 npm 命令
scripts/          本地安装、构建、预览、检查等脚本
.github/          GitHub Actions 工作流
.tools/           本地工具和辅助文件，已忽略 Git 提交
```

### 第四组：自动生成的文件

```text
dist/             整个网站的构建结果
courses/某门课/theme/    构建时复制进去的主题副本
```

有些工具还会生成课程内的 `book/`。这些目录的共同点是：能由源文件重新生成。长期修改应保存在源文件中。

## 3. 一门课程里面有什么

以当前正在看的 Web 开发为例，结构已经从空模板扩展成了：

```text
courses/
└── web开发/
    ├── course.json
    ├── book.toml
    ├── experiments/
    └── src/
        ├── SUMMARY.md
        ├── introduction.md
        ├── first-note.md
        ├── resources.md
        ├── my-cs/
        │   ├── 目录结构与网址.md
        │   ├── Markdown与mdBook.md
        │   └── ...
        ├── images/
        │   └── my-cs/
        └── demos/
            └── mini-site/
                ├── index.html
                ├── style.css
                └── main.js
```

这几个文件需要重点区分：

| 文件 | 回答的问题 | 修改后主要影响哪里 |
| --- | --- | --- |
| `course.json` | 在课程清单里叫什么、排第几 | 独立课程目录页上的卡片 |
| `book.toml` | 这本书叫什么、正文在哪、用什么主题 | 书的构建与阅读设置 |
| `src/SUMMARY.md` | 文章有哪些、按什么顺序读 | 左侧课程目录 |
| `src/introduction.md` | 打开课程先看到什么 | 课程介绍页 |
| `src/某篇笔记.md` | 具体要讲什么 | 笔记正文 |

假设你想把课程卡片的简介写详细，应改 `course.json` 的 `description`。想改某篇笔记的正文，则打开该篇 `.md` 文件。

## 4. 为什么有好几个 index.html

`index.html` 是常用的目录入口文件名。放在不同目录里，就对应不同的入口。

| 你看到的文件 | 实际用途 |
| --- | --- |
| 项目根目录 `index.html` | 首页源模板，带有待替换的变量 |
| `courses/index.html` | 全部课程的目录页源模板 |
| `resources/index.html` | 资源清单页源模板 |
| `dist/index.html` | 构建好的首页 |
| `dist/courses/index.html` | 构建好的课程目录页 |
| `dist/web开发/index.html` | mdBook 为这门课生成的入口 |
| `src/demos/mini-site/index.html` | 本课程的独立教学小网页 |

先看它在哪个文件夹，再判断用途。

## 5. 项目里的路径如何变成网址

my_cs 的线上部署入口是：

```text
https://fangdawei33.github.io/my_cs/
```

这个入口对应构建产物的 `dist/`。文件部署时，`dist` 这一层的名字不会出现在网址里。

| 源文件 | 构建产物 | 发布后的网址路径 |
| --- | --- | --- |
| 根目录 `index.html` | `dist/index.html` | `/my_cs/` |
| `courses/index.html` | `dist/courses/index.html` | `/my_cs/courses/` |
| `courses/web开发/src/first-note.md` | `dist/web开发/first-note.html` | `/my_cs/web开发/first-note.html` |
| `web/home.css` | `dist/assets/home.css` | `/my_cs/assets/home.css` |
| `life/src/introduction.md` | `dist/life/introduction.html` | `/my_cs/life/introduction.html` |

特别留意第三行：课程源码虽然集中放在 `courses/` 下，生成后的每本书却直接位于 `dist/课程目录/`。这是项目构建脚本的安排，因此进入某门课的 URL 不带额外的 `courses/`。

本地预览时，同一套产物通常对应：

```text
http://localhost:3000/
http://localhost:3000/courses/
http://localhost:3000/web开发/
```

本地预览把 `dist/` 当作站点入口，所以没有线上仓库路径中的 `/my_cs/`。

## 6. `./`、`../`、`/`、`#` 怎么区分

先假设浏览器正在打开：

```text
https://fangdawei33.github.io/my_cs/web开发/my-cs/目录结构与网址.html
```

| 写法 | 怎么理解 |
| --- | --- |
| `./` | 当前网页所在目录 |
| `../` | 从当前位置向上一层 |
| `/` 开头 | 从当前域名的根路径开始 |
| `#某个标识` | 当前网页内的某个位置 |
| `https://...` | 一个完整的网络地址 |

例如 `../images/my-cs/示意图.svg` 从 `my-cs/` 回到这门课的目录，再进入 `images/my-cs/`。

如果在网站首页写：

```html
<a href="./courses/">课程笔记</a>
<a href="#about">关于这里</a>
```

第一个链接打开课程目录页；第二个链接在当前页面中寻找 `id="about"` 的区域。之前点击“学习方式”跳到页面底部，就是这类页内链接的效果。

如果你希望切换到另一个页面，应给它写目标页面的地址，而不是只写一个 `#` 标识。

### 为什么不随便写 `/assets/home.css`

`/assets/home.css` 会从域名根开始查找：

```text
https://fangdawei33.github.io/assets/home.css
```

但 my_cs 当前实际发布在 `/my_cs/` 下。首页使用 `./assets/home.css`，就能从当前项目入口找到样式，在本地预览和线上项目路径下都适用。

### 中文路径可以直接写

```markdown
[阅读编译原理](../../编译原理/)
```

这里是在当前这个嵌套笔记页中跨到另一门课，才使用两个 `../`。同一链接放在课程介绍页里，层级就需要重新计算。

浏览器显示或复制中文地址时，可能变成 `%E7...` 的形式；自己写文章时通常可以直接使用中文路径。

## 7. 两个 assets 为什么看起来不一样

它们的完整位置不同：

```text
my_cs/assets/             GitHub README 的封面等素材
my_cs/dist/assets/        网站构建后的公共素材
```

后者主要由 `web/` 复制而来：

```text
web/illustrations/life.png
            ↓ 构建时复制
dist/assets/illustrations/life.png
```

所以，把图片仅放进根目录 `assets/`，不会让它自动出现在网站的 `dist/assets/` 中。README 图片和网站图片，应按各自实际引用的位置保存。

课程笔记里的图片则可以放在本课程 `src/images/`，由 mdBook 随书复制。
